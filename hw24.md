📌 Основная задача
Реализовать API для управления пользователями.
📌 Структура пользователя
Создать структуру:
type User struct {
 ID   int    `json:"id"`
 Name string `json:"name"`
}
📌 Хранение данных
Данные должны храниться в JSON файле.
Например:
users.json
📌 Требования к API
🔹 Создание пользователя
Endpoint
POST /users
Что должен делать
принимать JSON
декодировать пользователя
сохранять пользователя в файл
возвращать успешный ответ
🔹 Получение всех пользователей
Endpoint
GET /users
Что должен делать
читать пользователей из файла
возвращать список пользователей в JSON формате
🔹 Получение пользователя по ID
Endpoint
GET /users/{id}
Что должен делать
получать ID из URL
находить пользователя
возвращать пользователя в JSON
Если пользователь не найден
вернуть:
404 Not Found
🔹 Обновление пользователя
Endpoint
PUT /users/{id}
Что должен делать
получить ID из URL
найти пользователя
обновить данные
сохранить изменения в файл
Если пользователь не найден
вернуть:
404 Not Found
📌 Middleware
Реализовать минимум 2 middleware.
🔹 Logging Middleware
Должен логировать:
METHOD PATH
🔹 Auth Middleware
Должен проверять header:
Authorization
Если header отсутствует или неверный
вернуть:
401 Unauthorized
📌 Конкурентность
Так как файл общий для всех запросов:
необходимо обеспечить безопасную работу с данными.
Можно использовать:
sync.Mutex
или другой механизм синхронизации
📌 Работа с JSON
Использовать:
json.Marshal
json.Unmarshal
или json.NewEncoder / json.NewDecoder
📌 Работа с файлами
Сервис должен:
уметь читать файл
уметь обновлять файл
корректно работать, если файл пустой или ещё не создан
📌 Дополнительные требования
Желательно:
проверка HTTP метода
корректные status code
обработка ошибок
разделение кода по функциям


Можно добавить:
удаление пользователя
middleware для времени выполнения запроса
graceful shutdown через context
валидацию входящих данных
